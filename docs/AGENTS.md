# AGENTS.md: the docs site

Guidance for AI coding agents (and humans) working on the site in `docs/`: [VitePress](https://vitepress.dev) 1.x, published at `https://pixelbar.nl/pixel-phone/`, and themed like [pixelbar.nl/pixel](https://pixelbar.nl/pixel) the way [spacestate](https://github.com/pixelbar/spacestate) is.

For the service itself, see the [root `AGENTS.md`](../AGENTS.md). Its rules apply to anything the site says.

## Stay in scope

- **The pages are the maintainer docs.** `architecture.md`, `infra.md`, `events.md`, `home-assistant.md`, `runbook.md` and `adr/` belong to the service and change in the same pull request as the code they describe. A site change never rewrites them to fit the theme.
- **Only two pages are the site's own:** `index.md` (the overview) and `accept-api.md` (one component). The overview's state diagram is a copy of the README's: change both together.
- **Don't move a doc.** `AGENTS.md`, the README, tests and the code link to `docs/*.md`, and tests read `events.md` and `openapi.yaml`.
- Site work outside `docs/` is limited to the `docs-*` and `pixel-theme` recipes in `justfile`, `scripts/pixel-theme.sh`, the docs entries in `.gitignore` and `biome.json`, the `docs` list in `.github/path-filters.yml`, `.github/workflows/docs.yml` and a `CHANGELOG.md` entry.

## Commands

From the repository root:

```sh
just docs-install   # the site's dependencies (its own lockfile)
just docs-dev       # http://localhost:5173 with hot reload
just docs-build     # docs/.vitepress/dist; fails on a dead link; must pass before a change is done
just docs-preview   # serve the last build
just pixel-theme    # refresh theme/pixel.css from pixelbar.nl/pixel
just lint           # Biome, which also checks docs/
```

`docs/` is its own pnpm project (`package.json`, `pnpm-lock.yaml`, `pnpm-workspace.yaml`), as in Pixel, so nothing here reaches the image. Never add the site's dependencies to the root `package.json`.

## Layout

```
docs/
  index.md, accept-api.md   # the site's own pages
  *.md, adr/*.md            # the maintainer docs, served where they are (/runbook, /adr/0002-…)
  openapi.yaml              # the accept API; accept-api.md renders it
  .vitepress/
    config.ts               # nav, sidebar (ADRs are listed from docs/adr/), markdown plugins, the spec module
    markdown/               # repo links, mermaid fences, {{ }} escaping (from Pixel)
    theme/
      index.ts              # default theme without fonts, @fontsource fonts, pixel.css
      pixel.css             # GENERATED by `just pixel-theme`; never edit by hand
      Mermaid.vue           # diagrams in the Pixel colours (from spacestate)
      AcceptApi.vue, openapi.ts  # loads vitepress-openapi on the API page only
      openapi.css           # vitepress-openapi in the Pixel theme (from spacestate, scoped)
```

## The theme

- **`pixel.css` is a copy of /pixel's theme,** lifted from its live stylesheet by `scripts/pixel-theme.sh`, the same script spacestate uses. Regenerate it with `just pixel-theme` and commit the result: the build must not depend on /pixel being up. The script refuses to write a truncated file.
- **Use /pixel's tokens** (`--bg`, `--surface`, `--ink`, `--spectrum-*`, `--space-*`, `--font-*`). If you want one it doesn't have, add it to Pixel first; don't copy a value into a second place.
- **Fonts are self-hosted** through `@fontsource`, as on /pixel: visitors' browsers shouldn't contact Google.
- **Both colour modes:** the site follows the system and has a switch. Check light and dark, and 390px wide with no sideways scrolling.
- **`openapi.css`** is spacestate's, scoped to `.oa-single-page` (the API page's `pageClass`), because it stays loaded after a visit to that page. A new rule that could match an ordinary page needs that scope too.

## Markdown

- **Mermaid** fences render through `Mermaid.vue`, redrawn when the colour mode flips. A broken diagram shows its source and why it failed. Wide diagrams scroll sideways rather than shrink below 75%.
- **Links:** link between pages by file (`runbook.md#secrets`), so they work on GitHub too. Links to files outside the site (`../src/…`, `openapi.yaml`) become GitHub links at build time (`markdown/repo-links.ts`). Don't silence a dead link; fix it.
- **The accept API page** is `docs/openapi.yaml`, drawn by vitepress-openapi. Every operation needs a tag. vitepress-openapi is most of a megabyte, so `AcceptApi.vue` loads it on that page only.
- **The repository is public.** No secrets, tokens, Home Assistant URLs or real API keys, not even as examples.

## Adding pages

- **A maintainer doc:** add it at the root of `docs/` and to the sidebar in `config.ts`.
- **An ADR:** `adr/NNNN-title.md` with a `# NNNN. Title` heading is listed in the sidebar by itself. Also add it to the table in `architecture.md`.
- **Files that aren't pages** (like this one) go in `srcExclude` in `config.ts`.

## Dependencies

- VitePress, Vue, Mermaid, vitepress-openapi, `yaml` (to read the spec at build time) and the three `@fontsource` packages. Explain any addition in the PR.
- Pin exact versions, at least two weeks old. Commit `docs/pnpm-lock.yaml`.

## Publishing

`.github/workflows/docs.yml` lints and builds on every pull request that touches the site. It publishes to GitHub Pages when the Release workflow calls it with the release commit, or when a maintainer runs it by hand. See [the runbook](runbook.md#the-docs-site).
